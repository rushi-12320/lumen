Security

How {{brand}} Cloud protects your data

What we store, where, who can see it, and how to get it back or delete it.

Where your data lives

{{brand}} Cloud runs on Amazon Web Services in the Mumbai region (ap-south-1). Application servers, databases, backups and the GPU server for LLM jobs are all in that region.

Separation between customers

Every organisation has its own database file. The application opens only the database of the organisation the signed-in person belongs to (or that an API key belongs to); there are no shared tables of customer data.

Personal data in traces

Before a trace is stored, email addresses, phone numbers, card numbers, API keys and IP addresses are replaced by placeholders. You decide what your app sends; send less if you can.

Encryption

All traffic uses HTTPS (TLS). Disks and backups are encrypted at rest by AWS. API keys and session tokens are stored only as hashes; passwords as salted scrypt hashes.

Access

People sign in with email and password; sessions expire after 30 days and failed logins are rate limited. Inside an organisation, roles decide who can approve changes, create keys or manage billing. Our engineers access servers only through AWS Systems Manager (no open SSH port), and only to operate the service.

AI and LLM processing

LLM jobs run on our own GPU server (open models served with Ollama) in the same AWS region, only after a person in your organisation approves each job. We never send your data to a third-party AI provider, and we do not train models on it.

Backups and recovery

Databases are copied to encrypted, private Amazon S3 storage every 15 minutes (kept for 2 days), and a daily copy is kept for 35 days.

Audit trail

Inside the console, every decision (approvals, rollbacks, key changes, policy changes) is written to a hash-chained ledger that shows any later edit. Account actions (sign-ups, invitations, role and billing changes) are logged as well.

Your controls

Export your organisation's complete database from Settings > Data at any time. Deleting the organisation erases its database at once; backups expire within 35 days.
