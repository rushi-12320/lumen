Everything to connect an app, read what the console shows and run {{brand}} yourself.

Quickstart (5 minutes)

  1. Create a free account. Your organisation and a first project are created for you.
  2. In Get started (or Settings & Keys in the console), create an API key. It is shown once; we store only a hash.
  3. Add two lines to your Python app (below). Every LLM call appears in Traces within seconds, already checked.
  4. Invite your team in Settings > Team. Admins and owners approve fixes and LLM jobs.

Want to see the checks first? Open the live demo and use Try it: a sample support bot whose every answer is traced and checked.

Python SDK

Standard library only, Python 3.8+. init() traces every call of the OpenAI, Anthropic and Google Gemini libraries (normal, async and streaming), and of providers you use through the openai package (Azure OpenAI, Groq, Together, DeepSeek, vLLM, Ollama). Traces are sent in the background; a problem inside {{brand}} never breaks your app.

pip install {{public_url}}{{sdk_wheel}}
import lumen_sdk
lumen_sdk.init(api_key="lmn_…", host="{{public_url}}")   # or set LUMEN_API_KEY and LUMEN_HOST

# one request = one trace; LLM calls inside become its spans
with lumen_sdk.trace("rag_answer", input=question, user_id=user_id) as t:
    with t.span("retrieval", name="kb_search", input=question) as s:
        s.output = docs                               # turns on the groundedness check
    answer = client.chat.completions.create(model="gpt-4o-mini", messages=messages)
    t.output = answer.choices[0].message.content

# or: every call of a function is one trace
@lumen_sdk.observe("classify")
def classify(text): ...

tpl = lumen_sdk.get_prompt("rag_answer")   # the production prompt from the registry

The package is called lumen-llm-sdk (the name lumen-sdk on PyPI belongs to another project) and you import lumen_sdk. You can also copy the single file: curl -O {{public_url}}/sdk/lumen_sdk.py. Set your real model prices in Settings & Keys so cost per request is right; the defaults are examples.

OpenTelemetry (any language)

Any OpenTelemetry exporter can send to {{brand}}: JavaScript/TypeScript, Go, Java and .NET apps, LangChain and LlamaIndex (through OpenInference or OpenLLMetry) and the Vercel AI SDK. {{brand}} reads the OpenTelemetry GenAI conventions (gen_ai.*), OpenInference, OpenLLMetry and the Vercel AI SDK's attributes.

OTEL_EXPORTER_OTLP_TRACES_ENDPOINT={{public_url}}/v1/otlp/v1/traces
OTEL_EXPORTER_OTLP_TRACES_HEADERS=x-lumen-key=lmn_…

Protobuf and JSON are accepted, compressed or not. Spans of one request that arrive in different batches are joined into one trace when the request's top-level span arrives (or after 15 seconds).

REST API

All SDK endpoints take the header X-Lumen-Key. Base URL: {{public_url}}.

EndpointWhat it does
POST /v1/traces1 to 1,000 traces per call: {"traces": [{"name", "input", "output", "model", "latency_ms", "tokens_in", "tokens_out", "spans": [...], "metadata": {...}}]}. Returns how many were added.
POST /v1/otlp/v1/tracesOpenTelemetry trace export (OTLP over HTTP, protobuf or JSON). See OpenTelemetry.
POST /v1/experimentsScore a batch of outputs against a dataset and run the release gate (for CI).
GET /v1/prompts/{name}The prompt with the label production (or ?label= / ?version=).
curl -X POST {{public_url}}/v1/traces -H "X-Lumen-Key: lmn_…" -H "Content-Type: application/json" \
  -d '{"traces":[{"name":"hello","input":"Hi","output":"Hello!","model":"my-model","latency_ms":420}]}'

Errors: 401 bad key · 400 or 422 bad body · 429 monthly trace limit reached (the body says so).

Evaluations and the CI release gate

Every trace is checked online: not empty, valid JSON, PII leak, prompt injection, refusal, toxicity, groundedness (for RAG, against the retrieved context) and latency SLO. Offline, build datasets from real traces, run experiments, add exact-match or F1 scores, and optionally an LLM-as-judge on our GPU (needs approval). Your CI calls POST /v1/experiments; the gate passes only when the new version is at least as good as the baseline.

Alerts and incidents

New projects start with rules for error rate, p95 latency, PII in outputs, injection attempts and hourly cost. When one fires, an incident opens and the ops agent investigates: it compares prompt versions, collects failing traces into a regression dataset and proposes a remedy.

Approvals and LLM jobs

Agents never change anything on their own. A proposal (for example a rollback to the previous prompt version) is first challenged by a critic, then waits in Approvals until an admin or owner approves or rejects it, with their name. LLM jobs (judging answers, summaries) show how many calls they need and run on our GPU in Mumbai only after approval; they count against your monthly LLM calls.

Limits and retention

Limits are per organisation and month (see pricing). We email owners and admins at 80% and 100% of traces; above 100% new traces get 429 until the month ends or you upgrade. Traces older than your plan's retention are deleted automatically.

Your data

Each organisation has its own database. Admins can download all of it from Settings > Data (an SQLite file you can open with any SQLite tool). Owners can delete the organisation; its database is erased at once and backups expire within 35 days. Details: security and privacy policy.

Self-hosting

The same product runs on your own server with Docker: nothing leaves your network, and LLM jobs use your own Ollama. The Community edition is free; Enterprise adds support, SSO on request and help with security reviews.

docker compose up -d      # Lumen + Caddy with automatic HTTPS (see deploy/DEPLOY.md)
